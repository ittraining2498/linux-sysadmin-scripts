01

Offboard user accounts

Linux destructive

linux/bulk-delete-users.sh

Remove many user accounts in a single run — built for offboarding day.

  • Dry-run by default; changes require --apply
  • Protected account list and a default minimum UID of 1000
  • Archives existing home directories before deletion
  • Timestamped deletion log in /var/log/bulk-delete-users.log
Before you start

Linux · root access · review usernames and home paths

Debian-family tests reported in README

DRY-RUN PREVIEW
sudo ./linux/bulk-delete-users.sh alice bob carol
Usage notes & limitations

Deletion is irreversible. Review the source and home paths first. Do not lower --min-uid below 1000.

Run ./linux/bulk-delete-users.sh --help to read all options.

02

Onboard a team

Linux

linux/bulk-create-users.sh

Create a whole intake of users from one CSV file, with generated passwords.

  • Preview CSV accounts before creating them
  • Generated passwords and first-login password expiry by default
  • Existing usernames are skipped
  • Credentials saved to a file with mode 600
Before you start

Linux · root access · prepare staff.csv and existing groups

Debian-family tests reported in README

DRY-RUN PREVIEW
sudo ./linux/bulk-create-users.sh --file staff.csv
Usage notes & limitations

Preview first. The current parser supports simple CSV rows; avoid commas inside full names. Review group names before creating accounts.

Run ./linux/bulk-create-users.sh --help to read all options.

03

Check disk & inode usage

Linux

linux/check-disk.sh

Tell me which filesystems are about to fill up — and nothing else.

  • Block usage and optional inode checks
  • Configurable threshold with --warn
  • Quiet output with --quiet
  • Non-zero exit code when a threshold is reached
Before you start

Linux · GNU df · no root access required

Debian-family tests reported in README

READ-ONLY CHECK
./linux/check-disk.sh --warn 90 --inodes
Usage notes & limitations

Returns 0 when healthy and 1 at or above the threshold. A report is only as complete as the filesystems df can read.

Run ./linux/check-disk.sh --help to read all options.

Inspect a Proxmox node

Proxmox VE

proxmox/cluster-health.sh

A single page telling you whether this node — or the whole cluster — is in good shape.

  • Cluster quorum and node overview
  • Checks four Proxmox services
  • Storage usage and local filesystem report
  • Running and total VMs and containers
Before you start

Proxmox VE node · run as root for complete reporting

Live cluster test pending

READ-ONLY CHECK
./proxmox/cluster-health.sh --warn 90
Usage notes & limitations

Not verified on a live cluster. A failed cluster-status command can be reported as standalone; verify quorum independently.

Run ./proxmox/cluster-health.sh --help to read all options.
