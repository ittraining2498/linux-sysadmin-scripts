Sysadmin Scripts.

Scripts that are actually run on production servers — not demos. Every destructive tool is dry-run by default, protects system accounts, and backs up before it removes anything.

bulk-delete-users.sh

Linux destructive

Remove many user accounts in a single run — built for offboarding day.

  • Dry-run unless you pass --apply
  • Refuses root and every account below UID 1000
  • Archives each home directory to /var/backups/ before deleting
  • Kills the user's running processes so userdel cannot fail halfway
  • Writes a timestamped log of every action
# preview only — nothing is changed
sudo ./linux/bulk-delete-users.sh alice bob carol

# delete for real, removing home directories
sudo ./linux/bulk-delete-users.sh -f leavers.txt --apply --remove-home

bulk-create-users.sh

Linux

Create a whole intake of users from one CSV file, with generated passwords.

  • Reads username,full name,groups from CSV — header and # comments ignored
  • Generates a 16-character password with no ambiguous characters (no 0/O/1/l/I)
  • Forces a password change at first login
  • Skips accounts that already exist, so re-running is safe
  • Writes credentials to a chmod 600 file for secure hand-off
# preview what would be created
sudo ./linux/bulk-create-users.sh -f staff.csv

# create the accounts
sudo ./linux/bulk-create-users.sh -f staff.csv --apply

check-disk.sh

Linux

Tell me which filesystems are about to fill up — and nothing else.

  • Exits 1 when any filesystem is over the threshold, so cron and monitoring can use it
  • Optional inode check — the failure mode people forget until it bites
  • --quiet prints nothing while everything is healthy
  • Skips pseudo filesystems by default; override with --exclude
# warn at 90% and include inode usage
./linux/check-disk.sh -w 90 --inodes

# in cron: mail only when there is a problem
./linux/check-disk.sh -w 85 -q

cluster-health.sh

Proxmox VE

A single page telling you whether this node — or the whole cluster — is in good shape.

  • Quorum state and the list of cluster nodes
  • pve-cluster, pvedaemon, pveproxy, pvestatd service status
  • Every storage backend: active or not, and how full
  • Running versus total VMs and containers
  • Exits 1 when anything needs attention
# full report
./proxmox/cluster-health.sh

# only show problems, warn at 90% storage
./proxmox/cluster-health.sh -w 90 -q
